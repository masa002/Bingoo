# 技術選定

2026-11-19 に確定しました。本番（1,000 人、最大 1 万人）で使う構成です。数字は 2026-10-29 の調査時点のものです。

## 決めたこと

| 部分 | 使うもの |
|---|---|
| 画面（スマホ・大画面・主催） | Vite + TypeScript（フレームワークなし）。静的ファイルを GitHub Pages で配る。今のデモと同じビルド |
| サーバー | Cloudflare Workers + Durable Objects（TypeScript） |
| 通信 | WebSocket（Hibernation を使う。ライブラリは partyserver） |
| つながらない人向け | 状態の JSON を Workers の Cache に置き、SSE、ポーリングの順に切り替える |
| 記録 | Durable Objects のストレージ。数秒ごとに R2 へ退避する |
| 主催の認証 | ゲームごとの主催キーと TOTP で、期限の短いトークンを出す。必要なら Cloudflare Access を前に置く |
| 単体テスト | Vitest（`src/core` のゲームの規則が対象） |
| 費用 | Workers の有料プランで月 5 ドルほど |

## サーバーの形

- **抽選の本体（Game DO）を 1 つ置きます。** 山札、判定、演出の計画、景品の割り当てを受け持ちます。進行は Durable Object のアラームで進めるので、主催の端末が止まっても抽選は止まりません。
- **接続の受け口（DO）を複数置きます。** 参加者の WebSocket を 1 つあたり約 800 本ずつ受けて、Game DO からの配信を各端末へ送ります。1 万人でも、1 つあたりの接続数は上限（32,768 本）の約 2.5% です。
- **今のコードをそのまま使います。**
  - `src/core`（ゲームの規則）と `src/net/protocol.ts`（メッセージの型）は、サーバーとブラウザで共用します。
  - `src/demo/authority.ts` の処理を Game DO に移します。
  - 画面（`src/ui`）と演出（`src/fx`）は、メッセージを受けて動くだけなので変えません。
- **デモは非常用に残します。** ブラウザの中で動く権威は、Cloudflare や会場の回線が止まったときの非常用モードとして使えます。

## 選んだ理由

10 月 29 日に 4 つの案を比べ、3 人の審査役が別々に採点しました。全員がこの案を選んでいます（総合 8 / 8 / 8。次点は自前サーバーの 7 / 7 / 7）。

- **権威が会場の外にあります。** 主催の PC が壊れても、別の端末から続けられます。
- **1 万人でも余裕があります。** 接続の受け口を分けるので、再接続が一斉に来たときでも上限の 38〜62% に収まる見込みです。
- **サーバーの運用が要りません。** 1〜2 人で作れる工数（2 人で 6〜9 週）に収まります。

## 前提と、変わる条件

- **データを置く場所を日本に固定できません。** Durable Objects で場所を強制できるのは EU・米国などだけで、日本は「できれば日本寄り」の希望を出せるだけです。
- **保存するのは表示名だけにします。** メールアドレスなどの登録はしません。
- **国内保存が必須だと分かった場合だけ、載せ替えます。** 同じ設計のまま、Node.js + uWebSockets.js を AWS 東京で動かす構成にします。
- **この確定は「国内保存を求める社内規程はない」という前提に立っています。** 規程の有無はまだ確認できていません。

## 10 月 29 日のあとに決めた仕様への対応

- **本人宛てのメッセージ**（手元の演出の段階、モグラが狙うマス、ラストワン争奪の結果）: Game DO が全員分を計算して受け口へ渡し、受け口が 1 人ずつ送ります。
- **番号を全員同時に開ける**: 端末はサーバーの時刻に合わせます。公開は「この時刻に開く」と約 1 秒先を指定して送ります。番号は、この公開のメッセージで初めて送ります（PUSH の前には送りません）。
- **抽選機の型**: 型によって番号が見えるまでの時間が違うので、サーバーが決めて大画面とスマホの両方に配ります（デモで実装済み）。
- **モグラ撃退**: 叩いた数は、叩き終わったときに 1 人 1 通だけ送ります。受け口が集計して Game DO に渡します。届いた数の範囲はサーバーで確かめます。

## 作る前に確かめること

- 1 万接続の負荷試験（合格の基準を決めて行う）
- 試験中にデプロイして、全部の Durable Object が再起動したときの再接続の集中
- 1 つの IP アドレスから 1,000 接続を張ったとき（会場の Wi-Fi を想定）に、Cloudflare の攻撃対策に止められないか
