# 技術選定

2026-11-19 に確定しました。本番（1,000 人、最大 1 万人）で使う構成です。同じ日に、この構成でサーバーを実装しました（`worker/`）。

- 比べたときの数字は、2026-10-29 の調査時点のものです。
- 料金と制限の数字は、2026-11-19 に公式のページで確かめ直しました。載せる手順は [deploy.md](deploy.md) にあります。
- **まだ本物の Cloudflare には載せていません。**
- 手元のサーバー（`npm run cf:dev`）では、500 人をつないで、途中で全員を一度に切ってつなぎ直す負荷試験まで通っています（2026-11-19）。同じ PC の中での結果なので、本物の Cloudflare と回線での確認にはなりません。

## 決めたこと

| 部分 | 使うもの |
|---|---|
| 画面（スマホ・大画面・主催） | Vite + TypeScript（フレームワークなし）。静的ファイルを、サーバーと同じ Worker から配る（Workers Static Assets）。GitHub Pages は、一人用のデモとして残す |
| サーバー | Cloudflare Workers + Durable Objects（TypeScript。`worker/`） |
| 通信 | WebSocket（Hibernation を使う。ライブラリは partyserver） |
| つながらない人向け | SSE、ポーリングの順に切り替える。だれでも見られる今の状態は、JSON を Workers の Cache に 1 秒だけ置く |
| 記録 | Durable Objects の保存領域（SQLite）。R2 を有効にすると、5 秒に 1 回まで R2 にも写す（入れなくても動く） |
| 主催の認証 | ゲームを作るのは管理キー。進行は、ゲームごとの主催キーと認証アプリの 6 桁（必須。2026-11-20 から）でログインして、12 時間で切れるトークンを使う |
| 単体テスト | Vitest（`src/core` のゲームの規則、`src/engine` の進行、`src/net` の通信） |
| 負荷試験 | `tools/load.mjs`（Node.js だけで動く。仮の参加者をつないで、1 ゲームを最後まで回す） |
| 費用 | Workers の有料プランで月 5 ドルから。実際の使用量は、まだ測っていない |

## サーバーの形

```
ブラウザ ──HTTP・WebSocket──> Worker ──> Game（ゲームごとに 1 つ。進行役）
                                    └─> 受け口（参加者 800 人ごとに 1 つ + 大画面・主催用に 1 つ）
Game ──配信──> 受け口 ──> 各端末
受け口 ──操作・つながっている数──> Game
```

- **画面のファイルも、同じ Worker から配ります。** 画面と API が同じ URL になるので、つなぎ先の設定が要りません。`index.html` は 1 枚で、URL の `?g=コード` や `&view=stage` で画面を切り替えます。
- **抽選の本体（Game）を、ゲームごとに 1 つ置きます。** 山札、判定、演出の計画、景品の割り当てを受け持ちます。中身は `src/engine/engine.ts` で、通信も保存も知りません（試験は、偽の時計で 1 ゲームを最後まで回しています）。
- **進行は、保存した「段」とアラームで進めます。** 「いまどの段で、次に進むのはいつか」を保存して、その時刻にアラームで起こしてもらいます。処理の途中で待ちません。主催の端末が止まっても、サーバーが入れ替わっても、保存した段から続きができます。
- **接続の受け口を、複数置きます。** 参加者の番号で、800 人ごとに 1 つに分かれます。大画面と主催は、別の 1 つにつなぎます。1 万人なら、参加者用が 13 個です。Game からの配信を、各端末へ送ります。
  - 1 つあたりの接続は、多くても 800 本です。上限（32,768 本）の約 2.5% です（上限は 10 月 29 日の調査時点の数字で、今回は確かめ直せていません）。
  - 受け口は、接続がないときは眠ります（Hibernation）。眠っている間は、時間の料金がかかりません。
- **全員の画面を、同じ瞬間に動かします。** Game は、メッセージに「この時刻に画面へ渡す」（`at`）を付けて、0.7 秒（`LEAD_MS`）早く送ります。端末は、サーバーの時刻に合わせた時計で `at` まで待ってから、画面に渡します。回線の遅れが 0.7 秒より短ければ、番号は全員の画面で同時に出ます。
- **全員宛てと本人宛てを分けて送ります。** 全員に同じ部分は 1 回だけ文字列にして、本人宛ての部分（期待度の色、モグラが狙うマスなど）だけを 1 人ずつ足します。
- **切れたら、続きから戻ります。** 端末は、最後に受け取った通し番号を付けてつなぎ直します。受け口は直近の 96 通を覚えていて、見逃した分が新しければ（2.5 秒以内）、続きを流します。古ければ、Game から「いまの状態」をもらって渡します。
  - つなぎ直しの待ち時間には、端末ごとにばらつきを付けます。1 万人が同時に切れても、一度に戻ってきません。
- **リハーサルができます。** 主催コンソールから、仮想の参加者を足せます（受付中だけ）。1 人でも、1,000 人の会を通しで試せます。
- **今のコードをそのまま使っています。**
  - `src/core`（ゲームの規則）と `src/net/protocol.ts`（メッセージの型）は、サーバーとブラウザで共用です。通信の約束は `src/net/wire.ts` にまとめました。
  - 画面（`src/ui`）と演出（`src/fx`）は、メッセージを受けて動くだけなので、デモと本番で同じものを使います。
- **デモは残します。** ブラウザの中で動く権威（`src/demo`）は、GitHub Pages で一人用のデモとして動きます。Cloudflare や会場の回線が止まったときの非常用にも使えますが、参加者のスマホはつながりません。

## 選んだ理由

10 月 29 日に 4 つの案を比べ、3 人の審査役が別々に採点しました。全員がこの案を選んでいます（総合 8 / 8 / 8。次点は自前サーバーの 7 / 7 / 7）。

- **権威が会場の外にあります。** 主催の PC が壊れても、別の端末から続けられます。
- **1 万人でも余裕があります。** 接続の受け口を分けるので、再接続が一斉に来たときでも上限の 38〜62% に収まる見込みです（見込みです。まだ測っていません）。
- **サーバーの運用が要りません。** 1〜2 人で作れる工数（2 人で 6〜9 週）に収まります。

## 前提と、変わる条件

- **データを置く場所を日本に固定できません。** Durable Objects で場所を強制できるのは EU・米国などだけで、日本は「できればアジア寄り」の希望を出せるだけです（実装では、その希望を出しています）。
- **保存するのは表示名だけにします。** メールアドレスなどの登録はしません。サーバーの中のゲームのデータは、作ってから 48 時間で消します（R2 に写した分は、自動では消えません）。
- **国内保存が必須だと分かった場合だけ、載せ替えます。** 進行役（`src/engine`）は通信も保存も知らないので、同じ設計のまま、Node.js + uWebSockets.js を AWS 東京で動かす構成にできます。
- **この確定は「国内保存を求める社内規程はない」という前提に立っています。** 規程の有無はまだ確認できていません。

## 10 月 29 日のあとに決めた仕様への対応

- **本人宛てのメッセージ**（手元の演出の段階、モグラが狙うマス、ラストワン争奪の結果）: Game が全員分を計算して受け口へ渡し、受け口が 1 人ずつ送ります。
- **番号を全員同時に開ける**: 上の「全員の画面を、同じ瞬間に動かします」のとおりです。番号は、公開のメッセージで初めて送ります（先には送りません）。
- **抽選機の型**: 型によって番号が見えるまでの時間が違うので、サーバーが決めて大画面とスマホの両方に配ります。
- **モグラ撃退**: 叩いた数は、叩き終わったときに 1 人 1 通だけ Game に送ります。届いた数の範囲は、サーバーで確かめます。
  - 叩いている途中の数は、2 秒に 1 回、受け口に送ります。受け口が合計して、大画面の「会場で叩いた数」に出します（結果には使いません）。

## 本番の前に確かめること（本物の Cloudflare では、まだどれもやっていません）

打ち方は [deploy.md](deploy.md) の「本番の前に確かめること」にあります。

- 1 万接続の負荷試験（既定の合格の基準: つなげた 99.5% 以上、時刻に間に合った 99% 以上、番号の発表を受け取った 99.9% 以上）
- 試験中にデプロイして、Durable Object が入れ替わったときの再接続の集中
- 1 つの IP アドレスから 1,000 接続を張ったとき（会場の Wi-Fi を想定）に、Cloudflare の攻撃対策に止められないか
- 1 回の会で、実際にどれだけ料金がかかるか
