# 演出と音の共通ルール

## 目的

- 後で使い回せる演出の部品を作る。ゲームの処理（core/）、通信（net/）、デモの権威（demo/）、画面（ui/）には依存しない。入力は引数で受け取り、終わりは Promise で返す。
- 目標は、ドーパミンが出る演出（オリパの開封、パチンコの予告・確定演出）。手を抜かず、こだわって作る。

## 画面と座標

- 大画面は 1920×1080、スマホは 390×844 の固定サイズで組む（画面側で縮小表示する）。host は position が relative か absolute の要素。
- 大画面の配置:
  - HUD: 上 0〜90px
  - 抽選機: 左〜中央（x 40〜1240、y 90〜790）
  - 結果パネル: 右（x 1270〜1880、y 110〜500）
  - 会場ビュー: 右（x 1270〜1880、y 520〜780）
  - 番号の盤: 下（y 800〜1060）
  - 抽選機以外の担当は、全画面に重ねてよい。
- スマホは上から、ステータス（〜40px。本番は名前と No. を 2 段で置く）、名前、リーチの帯、カード（5×5。上端 y=111 は動かさない）、出た番号の欄（いま出た番号・これまで）、知らせ、景品の札、会場の欄（「会場では」）の順に並ぶ。重ねる演出は host 全体（inset 0）に置く。
- 会場の欄は、大画面が見えない人（オンライン参加）のためのもの。自分のカードと手元の演出が主役なので控えめにし、期待度の色は使わない。会場の結果は、大画面と同じ瞬間か、それより後に出す（先に見せない）。
- スマホで番号を単独で見せる所は、いつも玉＋数字の部品（fx/phone/ball.ts）を使う（リール、リーチの帯、「あと」、出た番号、文の中の番号）。カードのマスだけは数字のまま。
- z-index の目安:
  - 大画面: 抽選機 1〜19、画面側のパネル 20〜29、イベント 30〜49、ダブルチャンス 50〜59、粒子 60
  - スマホ: カード 1〜9、あおり 10〜19、単発の演出 20〜29、景品・選択・ガラポン 30〜49

## 見た目

- 背景は濃紺（#05070f〜#16204a）。
- 段階の色は theme.ts の TIER_COLOR（青 #3b82f6、緑 #22c55e、赤 #ef4444、金 #f5c542）。
- 虹は RAINBOW_CSS を hue-rotate で回す。明るさは変えず、色だけを回す。
- 文字はシステムフォント（'Hiragino Sans', 'Yu Gothic UI', 'Meiryo', system-ui）。演出の大きな文字は font-weight 900。
- 画像・音声・フォントのファイルは使わない（CSS、SVG、Canvas で描く）。npm パッケージも追加しない。
- 色だけで情報を伝えない。形（● ▲ ◆ ★ ✦）と文字も重ねる。

## 画面をまたいでそろえる決まり（2026-11 のデザインレビューから）

- **文字の大きさ**: 大画面は、読ませる文字を 36px 以上、補足でも 28px 以上にする（会場の後ろの席に届かせる）。スマホは 13px 以上にする（飾りの英字を除く）。
- **言葉**: 「誰に、何が起きそうか」を、会場で口に出して自然な言葉で書く。
  - 司会が言う言葉、ビンゴで実際に言う言葉にする（「あった！」「リーチ！」「あと 1 つ！」）。短くして、「〜します」「〜です」の説明文にしない。
  - 硬い名詞・抽象的な言葉・翻訳調を避ける（静か、下位、公開、持ち主、獲得、判定、「この番号は、あなたのカードに当たる？」など）。
  - パチンコや業界の言葉、若者言葉は使わない。英語の飾り文字に意味を持たせない。
  - 同じものは、どの画面でも同じ言葉で呼ぶ: 番号は「出る・発表」、カードに番号が「ある・あった・なかった」、マスが「あく」、モグラを「たたく」、画面を「タップ」、景品を「受け取る・もらえる」、いちばん下の段階は「まだまだ」（theme.ts の `TIER_QUIET`）。「当たり・はずれ」は、くじ・ガラポン・景品に使う。
- **期待度（色の段階）はスマホだけ**: 青 → 緑 → 赤 → 金 → 虹の予告は、スマホに「自分のカードの話」として出す。大画面（会場）には出さない。
  - 会場と自分の 2 本を出すと、同じ回に色が食い違う（会場は金なのに自分は青、など）。2026-11 にユーザーの判断でやめた。
  - 大画面の抽選機は、どの回も同じ調子で回して番号を出し、着地のあとに結果（ビンゴ N 人！）を伝える。金の光は、ビンゴが出たあとの結果の表示にだけ使う。
  - 会場の盛り上がりは、イベント（緊急クエストなど）で作る。
  - カードは本人に見えているので、いまのカードで起こりえない言葉は出さない（リーチでない人に「ビンゴのチャンス！」を出さない）。段階の抽選は core/show.ts の `personalTier` が頭打ちにしている。
- **見出しの型**: 太さ 900、塗りは金のグラデーション `linear-gradient(180deg, #fff4cc, #f5c542 55%, #d9a520)`、縁は濃い茶 `#2a1a05`。虹（全員確定・ビンゴ確定）だけは例外。
- **虹**: 面（帯・文字・札）は横のグラデーション（theme.ts の `RAINBOW_FACE_CSS`）、玉は円すい（`RAINBOW_CSS`）。紫の単色で虹を表さない。全面の虹は「確定」だけに使う。
- **「あなた」の印**: 水色の札（地 `#5ad2ff`、文字 `#06223a`）。
- **主ボタン**（いま押してほしいボタン）: 金から橙のグラデーション `linear-gradient(135deg, #f5c542, #ff8a3d)`、文字 `#1a1400`。取り返しのつかない選択（景品を手放すなど）は主ボタンにせず、何を失うかをボタンの中に書く。
- **良い結果と悪い結果の色**: 守った・成功は緑 `#22c55e` と ◆、やられた・失敗は灰青 `#94a3b8` と ▼。紫 `#b98cff` は上位チャレンジ専用。
- **景品のレア度の色**（theme.ts の `RARITY_COLOR`）: C 銀、R 青緑、SR 金、UR 虹。段階の青（静か）と紛れないよう、R は青にしない。
- **外れたときの後味**: 外れ・失敗の画面には、次につながる一言を添える。下位の順位など、追い打ちになる数字は出さない。
- **大画面に出さないもの**: 期待度の予告（上の決まり）、見ている人が操作できないもの（ボタンなど）、司会向けの指示。司会の操作は主催コンソールにだけ出す。
- **参加者の操作が要るイベント**: いきなり始めない。先に説明の画面（何が起きるか・何をすればいいか）を出して、司会の合図を待つ。

## 安全（光過敏への配慮。必ず守る）

- 点滅は、どの要素も 1 秒に 3 回以下。
- 全面が光る演出は、1 回の演出につき 1 回まで。輝度の変化は 20% 以下、立ち上がりは 120ms 以上。
- 赤は点滅に使わない。縞・渦巻・同心円は画面の 1/3 以下の面積で、ゆっくり回す（1 秒に 0.1 回転以下）。
- 揺れは金と虹のときだけ（8px 以内、300ms 以内）。
- prefers-reduced-motion のときは、動きを止めて色と文字だけで伝える（runtime.ts の prefersReducedMotion）。

## 時間

- runtime.ts の Timeline を使う（speed で縮み、cancel で止まる）。setTimeout を直接使わない。CSS アニメーションの長さは tl.ms(x) で決める。
- デモには ×0.5〜×4 の速度切り替えがある。speed が変わっても崩れないようにする。

## 音

- `import { sfx, bgm, engine } from '../../audio'` で、名前だけを呼ぶ。名前の一覧と意味は src/audio/types.ts にある。
- 中身は別の担当が並行して作っている（今は鳴らない仮の実装）。
- 本番ではスマホは既定で音を出さない（会場で 1,000 台が一斉に鳴るとうるさい）。会場の外から参加する人のために、右上のボタンで本人が入れたときだけ鳴らす（ui/phone.ts）。デモでは同じ PC から鳴るので、スマホの演出の音は控えめにする。

## 粒子

- src/fx/particles.ts の Particles（Canvas 2D の紙吹雪・火花）を使ってよい。

## ギャラリー

- 自分のフォルダに `*.gallery.ts` を置き、src/fx/gallery.ts の registerGallery で、作った演出や音をすべて登録する。
- `npm run dev` で開いた URL に `?gallery` を付けると、一覧から 1 つずつ再生できる。
- play(host, tl) の host は、screen が 'stage' なら 1920×1080、'phone' なら 390×844 の要素。

## コード

- TypeScript（strict）。コメントは日本語で、既存のコードと同じくらいの量にする。
- CSS は担当の接頭辞を付けたクラス名で書き、TS から import する（例: `import './draw.css'`）。
- 自分の担当ファイル以外は編集しない（読むのはよい）。
- 共通のファイル（theme.ts、runtime.ts、gallery.ts、audio/types.ts、audio/engine.ts、audio/index.ts）に足りないものがあれば、自分のファイルの中に書く。
- 確認は `npx tsc --noEmit` が通ることだけでよい。ブラウザでの確認は、統合のときにまとめて行う。
